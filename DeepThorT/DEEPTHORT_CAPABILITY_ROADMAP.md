# DeepThorT capability comparison and development roadmap
Review: 24 November 2026. Baseline source 2b4bdec (previous CI failed three GUI fixtures; corrected in this pass). This is a documented feature comparison, not a measured model benchmark. LLM means Simon Willison's LLM CLI as well as the underlying model layer. Current source is v61; do not conflate source with released Windows v60.

## Architecture that must remain
Local Qwen2.5-Coder-1.5B-Instruct ONNX; JANUS and Sentinel independent persistent coordinators; preserve exact original specification and amendments, current eight-tab desktop, saved projects, state, and verified source. Gaming-first shared 30% CPU and committed-memory cap; no cloud fallback, no arbitrary unreviewed execution, normal Windows UAC. Do not add Ollama, llama.cpp or additional LLMs as a shortcut. No project-specific hardcoded plans. Smaller model quality is not equivalent to larger hosted models, and agent orchestration cannot guarantee equivalence.

## Ordered implementation backlog
Each pass requires actual source integration, adversarial regression tests, green CI and preserved old state. No capability is marked complete from this list alone.
1. Restore green baseline; named unittest receipts, exact requirement links and stale-state checks. Next: expose persistent trace in existing Work queue, bind named receipts to verification and extend to GUT/.NET/npm structured runner outputs. Link unlabelled exact indexed requirement spans through Sentinel-reviewed mappings; reject unsupported/unknown coverage and skip-only tests. Validate test oracles via deliberate wrong behavior in isolated test fixtures, never silently alter tests.
2. Repository intelligence: incremental local SQLite path/symbol/definition/reference index, Python AST first then GDScript/XML/JS and language-server adapters. Ranked file/snippet retrieval under context budget, exact hashes, read-only protection, dependency traversal. Accept on a multi-file repair fixture where needed interface is outside current step; ensure stale/deleted files disappear.
3. Native agent tool bus: schema-validated read/list/search/symbol/diff/diagnostic actions, fixed argument vectors and bounded results, provenance and typed continuation. Reuse existing grants, Sentinel, cancellation and resource limits. Generalized reviewable plan/execute/observe loop; do not let untrusted output grant capabilities.
4. Git-aware development: detect dirty tree, read-only diff/status/log, reviewable multi-file patch transactions with rollback; later isolated worktrees, tests/commit with explicit branch authority, no push by default, no destructive reset. Respect projects without Git.
5. Context and memory: project-scoped reusable indexed evidence, compact session summaries with immutable source and amendment IDs, exact-file citations and recoverable checkpoints; bounded token budgeting/working-set prioritization. Distinguish semantic claims from evidence; no prompt truncation of authoritative scope.
6. Reusable skills and adapters: validated local skill manifest, versioned procedural evidence, resource-scoped allow/deny/ask, fixed pre/post validation hooks, later local MCP discovery and consent. Never execute arbitrary third-party plugins merely because their description requests it.
7. Application interoperability: verified catalog discovery, version-specific help/API docs, automatic required app acquisition under existing policy, CLI and native document/model/media adapters, durable repair of invalid results. Extend Godot import+runtime to actual project initialization and dependency-aware tests; Blender dimensions/collision/scene, X4 mod packaging/installation/test evidence, Android build/emulator tests.
8. GUI and visual verification: isolated process/window screenshots with local visual analysis, explicit reviewed interaction scripts within test desktop, safe input routing, no foreground focus manipulation. Distinguish screenshot/visual evidence from gameplay/functional proof.
9. Execution isolation and operations: measured CPU/memory/disk pressure, process-tree cancellation/timeouts, restricted child rights, capability-specific network controls, safe credentials handling, per-job logs and durable scheduler leases. Do not label ordinary Windows user permissions a sandbox.
10. Usability: retain current tabs; add search, linked diffs, trace status, meaningful blocked reasons, pause/resume/stop, reproducible diagnostics and optional headless CLI. Avoid redundant approval prompts while preserving standing project grants.
11. Evaluation and release: repeatable tasks with hidden independent acceptance: small Python multi-file app, existing bug fix, Godot game, X4 PE asteroid ship, Faction Command Android, document/3D asset workflow. Compare same task and hardware, report successful requirements, runtime, peak resources, token throughput, interventions, regressions, failures and reproducible logs. Compare OpenCode with same local model where feasible, then separately larger models; do not assert parity until measured. Build tested Windows installer with migration/rollback and user guide.

## Current limits
This pass does not run OpenCode, LLM, Codex, Cursor or Claude Code side-by-side. The actual ONNX model's end-to-end ability and native Windows/Godot/Blender functionality remain unproven. Priority is capability and evidence, not adding more models or duplicating features already implemented.

### Progress update — named Python evidence
Verbose Python verification requires named passing observations for approved supported test files, a persisted trace digest and current regression inputs, and displays current/stale evidence in Work queue. GUT/.NET/npm named receipts and reviewed unlabelled requirement mapping remain backlog. Next high-leverage pass: repository intelligence (priority 2).

### Progress — repository intelligence foundation
Implemented bounded persistent Python AST metadata, hash-checked retrieval, exact indexed-module import ranking, stale/deleted source removal and generation/repair context integration. Next: richer symbol reference/call graph and source excerpt selection, then GDScript/XML and other supported languages. No performance parity claim; benchmark end-to-end multi-file repair before claiming improvement.

### Progress — Python reference and impact analysis
Added observed call spellings, hash-checked short function excerpts, local-import reverse impact and regression input protection. Next extend the indexed languages to GDScript and XML with format-appropriate reference semantics; dynamic call targets and full language-server support remain open.

### Progress — Godot and XML repository intelligence
Schema 3 supports GDScript declarations, literal resource dependencies (including TSCN/TRES), typed unique XML macro/component references, stale-source filtering, and generation/regression context integration. Next: JavaScript/TypeScript and C# declarations and conservative module links; later language-server integration and measured end-to-end benchmark.

### Progress — web and C# source intelligence
Schema 4 adds lexical JS/TS/C# declaration retrieval, exact unambiguous relative module edges and unique C# namespace hints. This is conservative static analysis, not compiler-aware navigation; complex syntax can be omitted. Next priority 3: schema-validated repository tool interface and bounded JANUS tool-use loop. Language-server support and measured benchmark remain outstanding.

### Progress — typed agent tool interface
Priority 3 begins with a strict read-only repository tool registry and up to three adaptive JANUS selection turns using the existing council worker. Exact current source observations feed implementation/repair within the existing prompt budget; ordinary approval and Sentinel review remain unchanged. Next: persistent tool receipt inspection, diagnostic/diff actions and reviewed execution integration. No arbitrary shell or external tool capability added yet.

## AnythingLLM comparison — 24 November 2026

Official documentation: https://docs.anythingllm.com/chatting-with-documents/introduction ; https://docs.anythingllm.com/agent/overview ; https://docs.anythingllm.com/agent/intelligent-tool-selection ; https://docs.anythingllm.com/agent-flows/overview ; https://docs.anythingllm.com/mcp-compatibility/desktop ; https://docs.anythingllm.com/scheduled-jobs/getting-started ; https://docs.anythingllm.com/installation-desktop/overview ; https://docs.anythingllm.com/agent/custom/developer-guide . Documented features only, not a performance benchmark.

AnythingLLM provides workspace-scoped document RAG, embedding and reranking, flexible local/remote model backends, built-in/custom agent skills, intelligent tool selection, MCP, no-code flows, scheduled jobs and developer API. DeepThorT has persistent local development state, source/reference retrieval, strict original-specification governance, bounded native workflows, checkpoints and tested repair cycles; it does not yet demonstrate equivalent document ingestion/retrieval, general skills or integrations. Retain the local Qwen ONNX model and gaming-first restrictions. Additional prioritized work:

1. Extend priority 5 with local document ingestion (TXT/MD/PDF/DOCX and supported extracted text), hash-addressed chunks with page/line source citations, workspace scope, incremental reindex, user exclusion/deletion, lexical retrieval first and measured optional semantic embedding/reranking only within the existing resource/model constraints. Never treat retrieved text as authority or expose it across projects. Test with long manuals and exact citations; no additional language model.
2. Extend priority 3 with relevant tool shortlisting from task and previous observations, explicit tool schema, durable receipt and scoped capabilities. Compare retrieval accuracy and context cost with full registry, preserve fallback for missing tools. This pass implements the first durable read-only receipts, diagnostic and checkpoint diff observations; model selection quality remains unmeasured.
3. Extend priority 6 with reusable versioned flows/skills, typed inputs/outputs, review, dependency and permission checks, traceable execution, and an optional visual editor within existing desktop layout. MCP later with explicit local server trust, bounded inputs, per-capability approval, no arbitrary automatic execution.
4. Extend priority 9/10 with a disabled-by-default local authenticated developer API, job submission through existing approval gates, read-only progress and evidence endpoints, and user-directed recurring jobs with persistent history, no background work outside resource limits. Never expose localhost services or credentials to the internet by default.
5. Evaluate all additions on shared local hardware and representative knowledge-intensive software tasks before claiming parity. Multi-user hosting and cloud providers are not current priorities.

### Progress — intelligent tool selection
Task-aware permitted-tool shortlist, adaptive ranking from observed result shapes, explicit full-registry fallback, complete-record context packing and stale-observation rejection implemented. Three-turn limit preserved. Character budgets are conservative rather than exact tokenizer counts; actual token savings and selection accuracy require a live model benchmark. Next priority: typed structured execution requests through existing authority and queue (not arbitrary shell), then project document knowledge retrieval.

### Progress — structured execution request foundation
JANUS may request the already approved fixed project verification operation through a typed no-argument intent. Job/plan/spec binding, scheduler authorization, coalescing, result receipts and interruption handling are implemented. This first intent does not change the ordinary scheduler or permit arbitrary commands; additional reviewed operation types remain backlog. Next priority 5: workspace-scoped document knowledge retrieval (AnythingLLM comparison), starting with bounded local text ingestion and cited chunks.


### Progress — local document knowledge foundation
Added bounded, incremental project-scoped lexical indexing for UTF-8 TXT/MD/RST/ADOC and main-text DOCX. Persist hashed term postings and exact source positions, not document bodies; rehash and re-extract before retrieval. Existing reference scan enrolls eligible larger text/DOCX files, with explicit local CLI enrollment/removal and stale status. JANUS can request `document_search` through the existing bounded repository tool loop; planning receives context only within its existing optional evidence budget. DOCX citations identify extracted paragraph positions, not physical pages. PDF extraction, larger corpus discovery, dedicated desktop document controls, measured retrieval quality, and separately reviewed Sentinel document evidence remain next. No new model, shell authority or cloud dependency.


### Progress — page-cited PDF knowledge
Current baseline ed7b91c4 CI and Pages passed. Extended the existing document index with explicitly enrolled text-layer PDF manuals using a fixed local, version-pinned pypdf subprocess with bounded bytes/pages/text/time, exact source fingerprint and physical page/extracted-line positions. Ordinary workspace scans do not invoke the PDF parser. The worker never executes document actions, and the new optional dependency is installed explicitly; CI uses actual generated PDF fixtures. This is not OCR, sandboxing or native Windows acceptance. Next: bounded large-document discovery and dedicated workspace document controls, then measured retrieval and separately reviewed Sentinel evidence. Existing short reference, workflow/skill and source-index capabilities are not duplicated.
