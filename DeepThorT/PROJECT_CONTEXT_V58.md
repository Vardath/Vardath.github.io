When a single-file model proposal would shadow a specifically requested and inspected vanilla ship macro, the index remembers the source and its digest. The next bounded call asks the model for a new identifier. A successful choice and the associated index proposal are saved together. A changed source or two invalid compact replies return control to ordinary section planning. The recorded pair describes a ship identity and registration only.

The source adapter checks the extracted vanilla index, the ship source digest, the macro class and the component reference. It derives the variant from the actual source XML. Changes to an approved description or an existing destination follow the ordinary Build route. Source coverage currently depends on the candidates surfaced by the X4 inspection system.

Static acceptance verifies the registration name, resolved local path, and declaration for conventional full indexes and direct additions under /index. Selectors requiring a merged game index remain pending. Static acceptance establishes neither runtime loading nor docking clearance.
