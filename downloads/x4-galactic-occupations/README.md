# Galactic Occupations 0.5.5 — multilingual interface, station intelligence and crystal targeting

[Download Occupations](Galactic_Occupations_0.5.5.zip) · [All three updated mods](../x4-updates/) · [Log findings and live checks](vardath_galactic_occupations/LOG_REVIEW_0.4.8.md)

**November 14 multilingual release (v0.5.5):** Russian, French, German, Spanish, Italian, Czech, Polish, Brazilian Portuguese, Japanese, Korean, Simplified Chinese and Traditional Chinese now have complete 60-entry interface text tables with the native X4 language IDs. Both Spanish Steam regions use the game's standard Spanish L034 table. English L044 and language-neutral English remain as fallbacks. This changes **text only**; no save reset or gameplay code. Machine-assisted translations can be improved by native speakers. See [language details](LOCALIZATION.md). Runtime-generated status/logbook messages may remain in English, and live non-English clients have not been tested.

**November 13 occupation-feature release (v0.5.4):** The Station Scanner now publishes verified module identity and native scan information for each confirmed close-range sample. A new **EMP blueprint recovery** Behaviour toggle (off by default) lets an autonomous scanner consume exactly one actual Spacesuit EMP from the player's inventory to acquire an eligible missing module blueprint after the native Player HQ research requirements are met. This is a **simulated remote EMP/leak outcome**, not a physical suit EMP launch, data-leak spawn or a method of acquiring wharf/shipyard/equipment-dock blueprints. The autonomous Hacker has a persistent numeric **Hack objective** preference: 0 any, 1 production, 2 turrets, 3 shields, 4 storage, 5 radar, 6 construction, 7 station security. The existing station right-click menu still selects real panels individually. **Mine Crystals** now saves and temporarily suspends each selected turret's native asteroid-mining mode, explicitly aims at `class.crystal` targets, and restores the original mode when disabled. Enabled turrets from previous saves gain this safety behavior at the next controller poll. No new game, protected-UI replacement, payment, ship or crew reset. Automated source tests cannot confirm live X4 turret physics.

**November 13 spacesuit/redocking safety fix:** The latest X4 run recorded a Galactic Occupations v46 transporter-confirm observer forcibly teleporting the player back into the current ship at 15217.42 game seconds and issuing an emergency spacesuit exit at 15219.47. It followed a normal transporter confirmation on a ship during redocking. Version **0.5.3** disables the observer and delayed forced teleport/ejection entirely, while preserving all X4-native transporters and spacesuit interaction. Pending old saved requests are disarmed without moving the player. This is a causal safety repair of a proven unexpected action, although the debug log cannot establish exactly which physical collision placed the avatar inside the floor. No new game, orders, crew, jobs or wages are modified. The separate vanilla X4 9.00 floor-clipping problem may still occur.

**November 13 map UI safety hotfix:** The 13 November 2026 new-game debug log records 21 failed map info-frame builds, 52 table-width/scrollbar errors, 350 vertical-space failures and 312 invalid/destroyed-table calls. Galactic Occupations previously inserted a custom occupation-status row with an unsafe fixed 13-column span in the Map's dynamic Loadout table. Version 0.5.2 removes only that extra row; the ordinary Map information and **Mine Crystals** turret controls remain. The log does not prove this was the only contributor to the failures, and no live X4 game execution has yet confirmed the cure. Existing saves, passengers, orders, crew, jobs and payments are unaffected. On a new-game ship, greyed Deploy Military is expected when there are no mines or laser towers onboard.

**November 13 localization release:** The new language-neutral `t/0001.xml` supplies English labels, job descriptions and settings to non-English game clients, addressing `=ReadText191180-XXX=` errors. The English-specific file is retained for translation compatibility. The obsolete twenty-stop tooltip has been corrected to the actual ten-stop default; saved booking and job logic remain unchanged. See the [complete Nexus-ready description](NEXUS_DESCRIPTION.md). Full validation uses the 0.5.1 package. Live non-English localization still needs in-game confirmation.

**November 12 tour hotfix:** Tour catalogues now prune destroyed/stale points-of-interest from stored lists and force a fresh catalogue search on the next cycle. Tour booking checks validity before accessing a landmark's sector, eliminating the 156 invalid \`$poi.sector\` AI errors recorded in the 2026-11-11 evening log. Existing passengers, tour tickets, destinations, sightseeing progress and paid income are not reset. **0.5.0** also validates restored receipt records and their binding keys before annotating the vanilla transaction log; invalid saved records no longer crash `Vardath.NativeIncome.Payment`. The old `0.4.8_DEV` ZIP remains available as a historical compatibility link.

Galactic Sightseeing Tour accepts **S, M, L and XL ships**. Visible capital services use real ship/station transporter waypoints: the same booked NPC approaches the source, transfers to the receiving room, and must actually be aboard or ashore before the booking advances. Ten passengers maximum, available crew berths, existing fare conditions, ten-stop new bookings and cancellation rules remain.

The scanner now checks visible attention as well as loaded meshes and sector context before surface queries. Inactive geometry uses the existing timed remote survey path where enabled.

Exit X4, overwrite its Occupations folder and load your existing save. Keep Protected UI and Inventory Collector. No new UI, worker restart, passenger reset or changes to the Forge weapon. The separate Hyperion Ascendant and Compatibility 1.0.1 packages address the quest/ship and other logged errors.

459 Python contracts and 91 Lua mocks pass, with native-reference/XML/ZIP checks. **Native capital transporter, physics and save/load execution remain unverified in X4.** The supplied older-version log confirms 623 balance-matched payments totalling 994,060,000 Cr; those are not runtime tests of this release.
