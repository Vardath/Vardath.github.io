# Crystal mining repair — 0.2.5

## Evidence from debug(6).log

The supplied 24,309-line log loads manifest version 24 (0.2.4). All **20 crystal activity reports** say `Crystal miner waiting: select a compatible deployed beam turret, or disable beam-only`. Their task counters remain zero. This establishes a preflight restriction, not successful harvesting or collection. Inspection also found S/M-only Behaviour/Loadout eligibility, capital-ship rejection, no forward-weapon crystal path, captain-only storage and an automatic selling/holding-limit route inconsistent with the requested direct player-inventory delivery.

There are no new direct occupation AI/MD error messages in the session. Nine AI import warnings refer to saved older script contexts. Four explicit completed-work diagnostics belong to Trade Route Patrol. These are useful runtime observations of 0.2.4; they do not establish that the other occupations or the new 0.2.5 harvesting work succeeded. The existing screenshots and log do not demonstrate a completed luxury tour or passenger fare.

## Implemented changes

- **All normal ship sizes:** S, M, L and XL may select the crystal default behaviour. Forward guns, ordinary turrets and missile turrets have executable paths. Beam-only eligibility and the capital rejection are removed for crystal mining. Unarmed ships wait with a meaningful explanation. Repair/tug tools cannot be made to damage crystals, and launchers still need actual compatible ammunition.
- **Existing Loadout integration:** Mine Crystals is available on player ships of all four sizes and on missile turrets. Normal mode IDs, equipment, weapon groups, armed state and the Forge main weapon are not rewritten. The standalone near-ship controller yields whenever the default behaviour is Crystal Miner, preventing two controllers from aiming the same turrets at different deposits. Outside the occupation it remains a local turret controller, not a galaxy navigation/collection job.
- **Real deposit detection:** bounded searches inspect `class.crystal` components separately on each actual asteroid, following the native crystal-search pattern. This avoids assuming that one component-search object parameter can expand a list of asteroids. Checks are staggered and do not scan the galaxy every frame.
- **Physical firing:** the target remains the crystal component, not its parent rock. Ship clearance is included in approach distance, ranges come from available weapons, and native look-at/left/right/rear orientation attempts bring different firing arcs to bear. Forward weapons use native `shoot_at`; turrets use native aim/fire actions. No-damage attempts time out. The firing clock begins after approach/alignment. Friendly-traffic, station-proximity, hull and shield checks remain. Temporary region persistence is released when work ends or the order is interrupted.
- **Actual short-range collection:** only drops recorded from the targeted crystal's native drop event enter the queue. The ship approaches within a five-kilometre envelope plus hull clearance; native `collect_drop` consumes the real object and handles its contents. This is an explicit custom collection equivalent so large ships need neither an impossible collision pickup nor cargo drones/hold space for inventory crystals. A successful native pickup event or removed drop, plus actual player-inventory growth, gates reported delivery.
- **Immediate player inventory:** native collection can use captain inventory as a staging point. `forwardcrystals` removes only existing quantities of the five crystal wares from that captain, measures the actual withdrawal, adds that amount to player inventory, measures the actual addition and restores any uncredited remainder to the captain. There is no wait between withdrawal and credit, no timed item generation and no cash reward. Existing crystal stocks on an assigned miner's captain are forwarded too; unrelated inventory items are untouched.
- **No automatic selling or captain holding limit:** those current Behaviour controls are retired, along with beam-only. The miner keeps gathering for player inventory. Legacy worker parameter names remain internally for old saved callers. The old broker script forwards existing items instead of selling them if an old caller reaches it. It never sells the player's existing inventory. Item delivery is not a cash transaction, so no fictional financial ledger income is created; actual item transfers have General Logbook/debug records.
- **Recovery:** attributed pending drops survive task restarts and are retried before new harvesting. Invalid drops are pruned; unavailable ones get a bounded retry delay. Passenger actors, itineraries, diagnostic history, crew, equipment and other occupations' saved state remain intact. Ship ID codes are added to activity messages to distinguish identically named Kopis ships.

Only Galactic Occupations source changes. Inventory Collector and all six other repository extensions are not edited, replaced or required to be removed. If another collector removes a drop before this job's pickup, the job does not add a second copy. A third-party removal without a native collection/source event may not be attributable as this job's completed delivery; the job moves on rather than inventing evidence.

## What remains unverified

No runnable X4 installation, matching catalog set or save is available here. None of the new deposit hits, native pickup routing, live inventory transfers, missile compatibility or capital manoeuvres has been observed in X4. The supplied log proves the old miner never passed preflight, so it cannot prove the repaired harvesting path.

Crystal spawning/detection and physical weapon simulation remain engine-dependent. There is no fabricated off-screen destruction, substitute asteroid mining, free inventory grant or simulated success. When the necessary objects/physics are unavailable, the job reports the dependency and searches/waits; it cannot promise autonomous harvesting in an entirely unrendered sector. Existing attributed drops can still use the supported native collection action when the actual objects remain available.

Some weapons may not hit or damage a tiny crystal because of their arc, projectile size, range, ammunition or the engine's allowed target types. Every normal armed ship is eligible to try; engine weapon compatibility is still real. A capital with only very short-range weapons may have no collision-safe firing position. Such attempts must fail honestly without manufacturing crystals or changing its equipment.

## Reproducible in-game checks

1. Fully exit X4, replace Galactic Occupations, restart and load the existing save with Protected UI enabled. Check `Galactic Occupations 0.2.5 loaded`. Retained current default orders receive the versioned native parameter restart. Reassign any ship already on Hold Position; no new game is required by the implementation.
2. Start with a player-present asteroid field containing actual visible crystals. Use an S/M ship with **only a forward gun**, then one with an ordinary non-beam turret. Confirm the target is the deposit, observe actual hits/damage, released crystal drops and their removal. Check the five player-inventory counts before/after. Captain staging should drain immediately, cargo hold space should not matter, and cash should not increase.
3. Repeat with L and XL ships and with missile-only equipment carrying real ammunition. Observe the chosen stand-off and hull orientations, effective firing arcs and truthful no-damage recovery. Never treat assignment eligibility or a selected target as a proven weapon hit.
4. Check Mine Crystals in existing Loadout on an L/XL ship and missile turret. Select an ordinary mode again; it must reach the original handler with its normal ID. During the crystal default, the standalone MD controller must not select a competing deposit. Test a direct move order, then return to the default.
5. Verify no source inventory duplication: existing captain crystals move once to the player; a second forwarding pass does nothing; other captain inventory is retained. Transfer log entries are item counts, not payments. With Inventory Collector enabled, a drop removed by it must not be recreated or credited twice.
6. Save/load after harvesting and before pickup, and interrupt the ship with a direct order. Pending real drops should resume if still available; expired/collected drops should be skipped. Save/load and reassignment must not repeat old inventory additions.
7. Leave the sector and compare results with rendered simulation. Do not expect item gains for a timed wait or an unavailable deposit. Search the full debug log for `GO crystals/fire:`, `GO crystals:`, `GO completed:` and crystal activity reports. Match those reports to actual player-inventory changes and physical objects.
