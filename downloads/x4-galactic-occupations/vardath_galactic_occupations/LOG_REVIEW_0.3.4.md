## Docking, interruptions and existing saves

`vardath.go.dock` queues a native `DockAt` override only while the ship is executing its own occupation. This order is finite and contains actual destination/wait-time parameters. The adapter cannot create a second pending dock order. Its lifecycle watcher cancels only the exact owned order when a new player order appears, ownership/docking permission changes or the deadline expires. Previously queued user orders are snapshotted and retained. Native critical docking stages retain normal game cancellation semantics.

When an older nested docking call has left the active occupation default critical, the adapter repairs it at a completed travel/undocking boundary: snapshot every declared setting, use the documented critical-to-finish transition, and recreate the same mod default with those exact values. Persistent passengers, route progress, tools, stock, payment IDs and statistics remain in their existing player-entity tables. Player defaults and a deployed hacker are excluded. A planned docking order is recognised by the hacker's existing actor recovery instead of being mistaken for a user cancellation.

A failed docking attempt preserves passengers, tools and sale stock. Taxi and tours can replace a refused or unavailable docking destination while retaining the same real manifest. Failed empty pickups and crystal-sale docks can select another eligible station after recording the failed target. No timer, pending order, native return code, arrival alone or missing reference pays a fare. Full actual passenger disembarkation remains required. Simulated crystal sales still consume only a finite saved batch and credit only observed money.

**Orders already replaced by Hold Position must be reassigned once by the player.** An intentional Hold is indistinguishable from an old lost behaviour without its failure event, so this update does not overwrite arbitrary player Holds. Existing active occupations receive version recovery. Reassigning Taxi/Tour retains the saved manifest for its original service. Use `GO behaviour startup:`, `GO behaviour ended:`, `GO travel:`, `GO docking queued:` and `GO docking ended:` if another startup/arrival fails.
