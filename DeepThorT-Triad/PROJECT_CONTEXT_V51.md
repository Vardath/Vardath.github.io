# DeepThorT v51 — concurrent JANUS instruction interpretation

Date: 23 November 2026. Starting point: verified v50 main branch. Hardware reported by user: 40 GB RAM. Requested behavior: let new user instructions be translated by JANUS/Sentinel while ONNX implementation is busy, and raise the aggregate PC cap from 20% to 30%.

**Changes:** `desktop_launcher.py` and `win_cpu_cap.py` configure a *single inherited Windows Job Object* with at most 30% aggregate CPU and a maximum 30% installed-RAM-sized committed-memory limit, adapting downward to preserve game reserve when memory is pressured. `desktop_app.py` optionally launches a second `inference_server.mjs` Node process (localhost 8766), with `role=council`, under that same parent job. The primary remains port 8765. The second starts only with the capped parent, main-model readiness, dynamic memory headroom and exact child PID/health match. A restart cap and memory-pressure termination avoid runaway workers. There are not two separate 30% quotas or two distinct trained LLMs. No cloud inference. ONNX inference worker and model weights are unchanged.

`deepthort_local/instruction_inbox.py` stores incoming original full messages in SQLite, separate from transient ONNX prompts and the approved job queue; claim/interrupt/review/dismiss/handoff operations are atomic. An explicit Chats action/keyboard shortcut allows messages to arrive while implementation inference runs. `deepthort_local/dual_onnx.py` performs a JANUS planner turn followed by independent Sentinel critical turn on the secondary ONNX. Only the translated action and acceptance check join the next *unapproved* planning pass: `generate_indexed_plan`, `repair_indexed_roadmap`, or a new standard draft. Existing approved steps, file authority and test execution do NOT accept unapproved scope changes. Malformed replies and overly long messages are flagged for review, not silently assumed to be correct.
