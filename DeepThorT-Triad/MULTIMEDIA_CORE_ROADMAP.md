# Dedicated multimedia AI core — user requirement, 26 November 2026

Retain JANUS, Sentinel and implementation language models and their existing governance. Add a fourth specialist multimedia service with a separate bounded queue and persistent state. It is a capability core, not a fourth generic LLM. Load visual model backends on demand; do not assume one neural model can produce images, temporal video, editable geometry, and physically based textures. The service must work concurrently with language-model inference and ordinary approved project tasks when measured capacity permits.

## Resource and hardware rules

- Shared root hard cap: 40% whole-machine CPU, up to 50% of physical RAM as aggregate committed-memory ceiling; keep adaptive free-memory reserve of 10% of physical RAM. This is not 50% for each process. On the recorded system (~39.88 GiB usable physical RAM), the theoretical ceiling is ~19.94 GiB, up from ~15.95 GiB; actual launch budget can be smaller.
- Existing model workers currently share a nested commit budget with only 1 GiB left for control. Raising the root ceiling alone does not guarantee multimedia headroom. Introduce explicit measured admission and a protected allocation for control, reasoning workers, and one multimedia backend. Do not shrink live groups or evict the three workers silently. If insufficient, defer the media job, persist progress, or offer a smaller profile.
- Keep CPU and memory job membership, kill-on-close, gaming-priority, cancellation, no uncapped subprocesses, no silent cloud inference, no unbounded disk or GPU activity. GPU acceleration requires separate compatibility and budget validation; the Job Object does not cap VRAM.
- Existing local image generator is CPU float32 Diffusers and unproven concurrently. Prefer native OpenVINO GenAI CPU backends with pinned model revisions, verified weights and license. No automatic model download without normal approval.

## First candidates and work sequence

1. Dedicated multimedia service, durable jobs, cancellation and resource admission. Use a quantized OpenVINO Stable Diffusion 1.5 INT8 candidate (https://huggingface.co/OpenVINO/stable-diffusion-v1-5-int8-ov); benchmark against SD-Turbo or a compact LCM-compatible model if faster and suitable under the cap. Review exact upstream revision, license and supported native pipeline before installation. Use existing OpenVINO runtime, avoid new incompatible Python stacks where possible. Start with 512x512 or smaller bounded output; no promise of acceptable latency or image quality until actual tests.
2. Image editing/conditioning: image-to-image, masks/inpainting where compatible, concept art, sprite sheets, icons, material albedo and texture generation. Add visual inspection and actual artifact checks. Seamless textures, normal/roughness/metallic maps require appropriate processing/validation; do not claim generated RGB maps are physically correct.
3. Complete the existing narrated video pipeline, then add frame animation, camera moves, transitions, captions, audio mixing, rendering and short neural image-to-video clips only if local model benchmark passes. OpenVINO exposes text/image-to-video pipelines (https://openvinotoolkit.github.io/openvino.genai/docs/use-cases/video-generation/), but they are not proven to fit this hardware. Prefer conventional FFmpeg/Blender rendering where necessary.
4. Editable 3D assets: initial route is language-guided Blender automation, parametric meshes, UVs, materials, textures, rigging, export and validation. Add image-to-mesh inference only after an actual compatible local benchmark. TRELLIS.2 currently calls for NVIDIA GPU memory >=24 GB (https://github.com/microsoft/TRELLIS.2); do not install as default on this AMD RX480-class system. Candidate compact reconstruction models must pass real CPU or supported GPU tests. Validate topology, normals, scale, materials, mesh/texture bindings and GLB/OBJ/FBX or project-specific output; not merely rendered pictures.
5. Extend to whole game/mod art production: generated assets must meet exact project dimensions, formats, naming, license and engine import requirements. Sentinel evaluates against original and amended specification and actual artifact evidence.

## Acceptance

Preserve all existing 16 checks and add dedicated multimedia checks. Real images generated under the 50% root and 40% CPU caps while all three resident language-model PIDs remain unchanged and complete real requests; log overlapping execution intervals and memory/CPU evidence, no retries caused by pressure or serial fallback. Test safe deferral under low headroom, cancellation and restart, stale inputs, invalid outputs and gaming mode. Test image and texture outputs, independently inspect rendered video, and validate actual imported 3D meshes in Blender/target engine. Model or tool discovery alone is not acceptance. Verify end-to-end on the user's Windows hardware before claiming usable concurrency. Resume the broader capability backlog after a tested production milestone.
