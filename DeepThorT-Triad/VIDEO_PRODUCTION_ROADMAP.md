# DeepThorTriad — end-to-end video production requirement

User amendment, 26 November 2026: Given an ordinary project prompt, Triad must be able to produce a complete video suitable for the user to upload to YouTube, including script generation, text-to-speech narration and relevant stock or locally generated images.

## Current source audit
- Existing: optional local image generation (local_image_engine.py), image input/attachment handling, FFmpeg detection/catalog installation, learned tool procedures and approved multi-tool workflows, structural PCM WAV checking.
- Not established: a working TTS model, license-aware stock asset acquisition, durable storyboard/timeline, script-to-narration timing, actual video rendering and audiovisual acceptance, or one-prompt orchestration. Video extensions are recognized as external artifacts but not validated as finished videos.
- Do not mark this capability complete on the basis of tool discovery, scripts, a slideshow mockup, or synthetic receipts.

## Required deliverable and architecture
1. JANUS interprets the prompt and creates a durable production brief: intended audience, factual research vs fiction, target duration, visual style, output aspect, narration language and delivery. Preserve exact user constraints and amendments; Sentinel reviews plan and every material revision.
2. Draft and revise a complete script, scene/shot list and timed storyboard. For factual material, keep source links and evidence/uncertainty; distinguish illustration and speculation from documentary evidence.
3. Implement a local/offline TTS adapter with a small compatible downloadable model, pinned sources/license and real audio validation. Benchmark candidates (e.g. Piper-class local synthesis) on this Windows machine before selecting; support voice selection, pronunciation, pauses, regeneration and user-provided audio. Do not require cloud text inference or another persistent reasoning model.
4. Asset sourcing: prefer user assets, locally generated images, public-domain or appropriately licensed stock sources. Track exact source URL, creator, license/usage terms, acquisition date, file hash, and attribution requirements; do not treat search thumbnails as permission. No scraping private accounts or paid-service bypass. Optional online source requires normal network policy. Reuse existing local image adapter only when model fits resource restrictions and works; support fallback diagrams, stock assets or manual input. Preserve user music and licensing.
5. Derive scene lengths from actual speech audio, not guessed word count. Build a resumable timeline with editable scene manifests, text overlays, transitions, captions/SRT, narration, optional music ducking, and consistent visual framing. Validate input hashes and asset rights, reject missing assets, re-render changed scenes only.
6. Use a reviewed FFmpeg/ffprobe adapter with bounded argument arrays, no arbitrary shell, fixed safe encoding options, temporary outputs and atomic publish. Render 1080p 16:9 H.264/AAC MP4 by default (user may request 9:16 Shorts or other formats), plus script, captions, asset/credit manifest, thumbnail and optional description/title. Output local files, not automatic publication. No upload unless explicitly requested and separately authorized.
7. Verify actual rendered stream properties (duration, width/height, codecs, frame rate, audio presence, non-silence where expected, synchronization bounds), full decode, caption timestamps, missing-frame/blank-frame checks, and representative visual/narration review. Structural checks are not proof of creative quality or factual correctness. Record independent stage evidence.
8. Run all acquisition, synthesis, generation and encoding under the shared 40% root CPU/committed-memory allowance and current gaming-first rules; bounded processes, cancellation, no surprise downloads, normal UAC. If a model or rendering operation cannot fit, defer or use compatible local alternatives; report limitations.
