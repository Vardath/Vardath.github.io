## Purpose and interpretation

This is the owner's requested consolidated missing-and-partial capability register, reordered from easiest to hardest estimated implementation within the existing JANUS application. It preserves every original entry and its original ID from the capability comparison, including entries whose complete integration was not established and integrated acceptance testing (an outstanding validation task rather than a product feature).

The rank describes estimated engineering effort, not value, urgency, user priority, guaranteed feasibility, or an instruction to begin implementation. Relative positions within an effort band are approximate; prerequisites may change the order. It is a qualitative estimate, not a timed benchmark. Before implementation, inspect the current source and verify whether the capability is already present, partial, intentionally restricted, or genuinely missing. Reuse existing capabilities rather than duplicate them. A working third-party tool is not equivalent to integrated, validated autonomous operation.

Preserve the original JANUS and Sentinel recursive societies, five assigned local intelligence models, existing project/approval/verification mechanisms and gaming-aware shared 50% CPU and up-to-65% RAM-sized aggregate commit ceiling. No automatic permission expansion, model replacement, cloud inference, purchase, backend change or resource-cap increase is authorized by this register. Secure external account connections and publishing/deployment require separate authorization; resource-intensive local multimedia/model capabilities may need alternative compatible tools or future hardware. Do not describe an isolated working directory as a security sandbox. Existing local machine limitations and native acceptance must be respected.

The 27 November expansion incorporates every distinct ability explicitly assessed as Partial in the original comparison. Full application rollback was already listed under ID 209 and is annotated rather than duplicated. Entries described as implemented but with unverified quality are not newly treated as missing merely because they need acceptance testing; ID 210 tracks integrated acceptance. Original IDs 1–210 are preserved; new partial IDs start at 211. Rank is recalculated by estimated *remaining* effort, including partial implementations. Similar capabilities may have different acceptance scopes (e.g. restricted execution and a true OS sandbox). No runtime, architecture, external account or model changes are authorized by the ranking.

## Effort bands (easiest to hardest)

- **A — Low effort: bounded local extensions:** Reuse current libraries, tools and approvals with bounded modifications. (78 entries.)
- **B — Moderate effort: new adapters and durable workflows:** New adapters, evidence checks or local workflows; requires end-to-end tests. (134 entries.)
- **C — Substantial effort: integrated application workflows:** Cross-system coordination, interface/security work or substantial workflow integration. (94 entries.)
- **D — High effort: complex model/production and infrastructure integrations:** Complex model production, infrastructure or isolation; compatibility and resources may block feasibility. (30 entries.)
