### Protected generation after confirmed Windows memory exhaustion
The 35% local test loaded 3/3 models, then exhausted the job commit budget during inference; desktop, broker and exporter reported MemoryError. Keep the 35% root CPU/commit ceiling. Put every resident model (including venv child processes) in a shared nested commit job with a 1 GiB control-process reserve subtracted from the actual root allowance. Default to one native generation at a time; retain all weights, no fallback or model swap. Concurrent requests may queue, so the concurrency test remains inconclusive unless genuine safe simultaneous native generation is observed. The new memory subjob is read back and membership checked before model readiness. This reserves headroom against model allocations, not against unrelated application/tool allocations. Long-context inference can still be blocked if model memory exceeds the new limit. The Windows preflight checks nested job construction and a native numerical operation; only local three-model acceptance proves model usability. Export retry avoids masking an original exception with a Windows temp-file lock. Launcher pauses on failed exit.
