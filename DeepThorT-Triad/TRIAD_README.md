# DeepThorT Triad — native OpenVINO test edition

Three separate, concurrently resident native IR CPU workers, no model swapping, cloud inference, ONNX Runtime, llama.cpp or Ollama for text inference. The original DeepThorT remains unchanged. Compact candidate models: implementation IBM Granite 4.1 3B code-calibrated INT4 (HarmenWessels community OpenVINO conversion, 1.85 GB, Apache-2.0); JANUS SmolLM3-3B INT4 (community OpenVINO conversion, 1.74 GB, Apache-2.0); Sentinel Qwen3-1.7B INT4 (OpenVINO conversion, 1.21 GB, Apache-2.0). Each exact repository revision is fixed in triad_profiles.py. No Python from model repositories is downloaded or run. Native GenAI version 2026.4.1.0 in private runtime/openvino-env.

Close original DeepThorT. Start START TRIAD.cmd, click Install AI and approve ~4.80 GB of native IR downloads plus runtime. Installer probes CPU numerical inference before weights, verifies file hashes from exact revision metadata, then individually loads and generates a synthetic answer from each model (smallest first). Interrupted files resume when server supports Range. Existing GGUF files, old CPU runtime and the previous three native model directories are unused but not deleted. The compact model set lives in models/triad-openvino-compact-v1. Existing state and projects preserved. Start AI requires all three installed and resident in separate capped native OpenVINO Python workers; installation tests are sequential only. Run latest test checks three PIDs and actual exact replies, not coding reliability. Optional old Florence ONNX vision subsystem remains separate and is not used by text workers.

The original Windows Job Object remains shared: 35% CPU and 35% aggregate committed memory; no GPU. Native IR non-mapped load requested, one thread, one stream per role; prompt + output limited to 4096 actual tokens. Initial weight sizes leave estimated headroom, not proof that actual combined allocations fit. No runtime fallback or silent model substitution. A native failure terminates the broker and its nested model jobs. Logs are retained for diagnosis. Host CI tests only source contracts unless explicitly running real models on Windows. Native runtime and real model accuracy remain unverified until installation smoke tests and concurrent acceptance pass.

Old Qwen release history/manuals and previous benchmark files are inherited historical artifacts, not this edition's acceptance results. 

The root Job Object now has a random name and is checked by actual membership and limit values even inside a nested cleanup job. A Windows virtual-environment launcher can have a different PID from the real serving interpreter; health must identify a PID belonging to the exact child job. Windows CI runs a real native OpenVINO numerical preflight under the shared cap, not a full three-model inference benchmark.

Long-context inference can still be blocked if model memory exceeds the new limit. The Windows preflight checks nested job construction and a native numerical operation; only local three-model acceptance proves model usability. Export retry avoids masking an original exception with a Windows temp-file lock. Launcher pauses on failed exit.
