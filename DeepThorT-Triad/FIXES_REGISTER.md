## Rules
- Stable FX IDs, ordered below by recommended implementation/acceptance sequence rather than severity alone. All are pending at creation; distinguish confirmed defect, documented restriction and validation gap. Reinspect current source before changing it.
- Preserve the five operative assignments, both 11-core societies, mandatory asynchronous Memory, project state, models, interface, exact approvals, local inference, and the automatic Medium/High policy (50/85% CPU; 65% cooperative/80% maximum startup commit; 15/10% reserve). No third profile, silent fallback, unauthorized downloads, cloud inference, permission expansion or unrelated work.
- Work in compact independently reviewable passes; update FIXES_PROGRESS.md in the same pass. Exact candidate and predecessor source/Windows CI must be green before merge, then verify integrated main. Never weaken tests to obtain green. Native evidence is a separate gate; a fixture is not production acceptance.
- Native tests requiring the owner's PC, installed model weights, external accounts, real games or optional hardware must be explicitly marked blocked until available. No installer until requested. Prior registers remain authoritative for their original scope; cross-reference rather than duplicate implementation.
- Closing an item requires recorded source evidence and applicable actual acceptance; report residual limitations. Scope changes require owner direction.
